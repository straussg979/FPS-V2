# COLD SECTOR

A tactical 5v5 first-person shooter that runs in the browser. Rounds work like Counter-Strike (economy,
plant or defuse the charge, one life per round) with Siege-style tactics on top: leaning, destructible
soft walls and hatches, reinforcements, specialist gadgets, drones and security cameras. Play against
bots, with friends in a lobby, in ranked 1v1 duels, or on always-on public servers. Everything (maps,
weapons, names) is original; textures, models and sounds are generated by the build.

The game is set in **Afghanistan** and ships with two maps, **Qalat Village** and **Sarai Bazaar**: mud-brick
houses with timber beams and domed roofs, a walled qala, a caravanserai, a covered bazaar, a truck stop and a
two-storey hotel, with detailed Hilux pickups and technicals, Corolla taxis, painted jingle trucks, a fuel
tanker and the wrecks of a T-55 and a BTR. The two teams are Vanguard (arid multicam, helmets, plate carriers) and Bastion
(olive camo, pakol caps, chest rigs). When you attack against bot defenders there is no preparation phase:
the bots start the round already set up. See **[AFGHANISTAN.md](AFGHANISTAN.md)** for a tour of both maps.

The server is Node.js and TypeScript. It runs the authoritative simulation at 64 Hz, one worker thread
per match, and sends delta snapshots at 32 Hz over a WebSocket. The browser client is Three.js. It uses
the same simulation code to predict your own movement, so input feels immediate even with a high ping.

## Run it

You need **Node.js 22** or newer.

**Quickest:** double-click **`start.cmd`** (Windows) or run **`./start.sh`** (macOS, Linux). The launcher checks that
Node.js 22+ is installed (and opens the download page if not), installs or repairs the dependencies when needed,
checks that the native modules load, picks the next free port if another program holds 5000, starts the game and
opens it in your browser. Close the window or press Ctrl+C to stop it.

Or by hand:

```bash
npm install
```

```bash
npm start
```

Then open **http://127.0.0.1:5000/**, create an account and press Play.

On Windows, if PowerShell says *running scripts is disabled on this system*, run `npm.cmd install` and
`npm.cmd start` instead (or use the Command Prompt). That is PowerShell's script policy, not the game.

The first `npm start` builds everything: the server bundle, the browser client and the game assets
(maps, textures, models, sounds). That takes about a minute. Later starts only rebuild what changed.
Accounts and matches are stored in `user/` (an SQLite file).

Other commands:

| Command | What it does |
|---|---|
| `npm run dev` | Rebuilds the client on every change and restarts the server when its code changes |
| `npm run build` | Forces a full rebuild |
| `npm run typecheck` | Type-checks shared, server and client |
| `npm run check-maps` | Map checks: routes and reachability, coplanar faces that would z-fight (must be zero), soldier mesh layering |
| `npm run fetch-assets` | Optional: downloads CC0 HDR skies from Poly Haven for nicer skies and lighting (otherwise the sky is procedural) |

Settings go in a `.env` file next to `package.json`. Copy `.env.example`, which lists every option.
None are needed for local play.

## Playing

* **Play** page: start a bot match (tick *Just watch* for a bots-only match you spectate), create a lobby (share its 6-letter code), queue for a ranked duel
  (Glicko-2 rating, 20 s ready check) or challenge a player by name. **Servers** lists the public servers
  from `data/servers.json`. Anyone can join one at any time; bots keep the teams full.
* **Profiles** show ratings and match history. **Leaderboard** ranks duel ratings.
* You can spectate any running match. Duel spectators watch 10 seconds behind the players.
* You can stop a match you started (a quick bot match, or your lobby's match): **Stop** next to it in the
  Play page's *Running matches*, or **Stop this match** in the in-game Esc menu. Everyone in it is told who stopped it.
  Public servers and ranked duels can't be stopped this way.
* Add `?lag=100` (and optionally `&jitter=20`) to a game URL to test with an artificial round trip.

## Graphics

The renderer (`client/src/game/world.ts`) draws, per frame: a half-resolution SSAO pre-pass (applied to ambient light
only), the backdrop (sky and far mountains with their own camera range), the scene, light shafts, the first-person
weapon, eye adaptation, bloom, the colour grade (warm highlights, cool shadows), ACES or AgX tone mapping and SMAA or
FXAA. The sun has 1-4 texel-snapped shadow cascades with contact-hardening soft shadows; lamps near you become real
lights (with shadows on high and ultra). Depth is reversed-Z in a float buffer where the browser supports it
(`?depth=standard` turns it off). Buildings have two levels of detail per 24 m cell: rounded, gently uneven walls
and small clutter near you, plain boxes further away; all of it is visual only, the collision is unchanged.
Every option is in Esc → Graphics and in `data/graphics_presets.json`. `?preset=low` on a game URL tries a preset
without saving it. See **[POLISH.md](POLISH.md)** for what each part does and the measurements.

## Put it on your domain with Cloudflare

The whole site uses one address and one port: pages, assets and the game connection
(`wss://<your domain>/ws`). It works behind Cloudflare's free plan, and a Cloudflare Tunnel means you
don't need to open any ports on your machine.

1. **Add your domain to Cloudflare** (free plan) and switch your registrar's nameservers to the ones
   Cloudflare gives you.
2. **Create a tunnel.** In the Cloudflare dashboard go to Zero Trust → Networks → Tunnels → Create a
   tunnel (cloudflared). Install `cloudflared` on the machine running the game as shown there. Add a
   *public hostname*, for example `play.example.org`, with service **`http://127.0.0.1:5000`**.
3. **Configure the server.** Create `.env` with:
   ```
   SITE_URL=https://play.example.org
   TRUSTED_PROXY=cloudflare
   ```
   `SITE_URL` is the only place your domain appears. `TRUSTED_PROXY=cloudflare` makes the server use
   the visitor's real IP (`CF-Connecting-IP`), but only when the request comes from Cloudflare's
   address ranges or from this machine (the tunnel). Login limits and rate limits then apply per visitor,
   not to the tunnel. Cookies become `Secure`.
4. **Start it** with `npm start`. Keep the default `HOST=127.0.0.1`: the tunnel connects locally, so
   nothing is exposed to the internet directly.
5. **Cloudflare settings** for the domain:
   * SSL/TLS → Edge Certificates → **Always Use HTTPS**: on.
   * Network → **WebSockets**: on (it is on by default).
   * Speed → Optimization → **Rocket Loader**: off. The pages already mark their scripts
     `data-cfasync="false"`, but turning it off avoids surprises.
   * Security → Bots: leave **Bot Fight Mode** off. On the Free plan it can't be skipped for one path, so
     it may challenge the game connection on `/ws`. (On paid plans, Super Bot Fight Mode can skip `/ws` with a
     WAF custom rule.) Use WAF custom rules and the game's own login limits against bots instead.
   * Caching → Cache Rules: add a rule for `URI Path starts with /assets/` → *Eligible for cache*, edge
     TTL *Use cache-control header*. Assets have content hashes in their names and are sent as
     `public, max-age=31536000, immutable`, so Cloudflare can cache them indefinitely. HTML and API
     responses are `no-store`.

**With Docker** instead: put `TUNNEL_TOKEN=<token from the tunnel page>` in `.env` together with the
settings above, set the tunnel's service to `http://127.0.0.1:5000`, and run

```bash
docker compose --profile tunnel up -d
```

The image builds the client and the assets at build time. Accounts are kept in the `game-data` volume.
`docker compose up -d` without the profile runs only the game, on `127.0.0.1:5000`.

**Hardware.** Each running match uses about one CPU core when it is full (64 Hz simulation plus bots).
Each player costs about 5–10 KB/s of upload. A small VPS or home machine with 2–4 cores handles
`MAX_MATCHES=4` (the default). Assets are about 100 MB and are served once per visitor, then from cache.

The server also handles:

* WebSocket pings every 20 s, well within Cloudflare's 100 s idle timeout.
* Reconnects with backoff. A dropped player keeps their slot for 60 s.
* On SIGTERM it closes connections cleanly and stops the match workers.
* `GET /healthz` reports status for uptime checks.
* Game connections from origins other than `SITE_URL` (and `ALLOWED_ORIGINS`) are refused.

## Project layout

| Path | Contents |
|---|---|
| `shared/` | Simulation code used by both server and client: collision, character and player motor, weapons data, level builder, skeleton and pose, the binary protocol, a CPython-compatible RNG |
| `server/` | Fastify site and `/ws` gateway (`src/web/`), match workers (`src/match/`), game simulation (`src/sim/`), bots (`src/ai/`), snapshots and input validation (`src/net/`) |
| `client/` | Site scripts (`src/site/`) and the 3D game (`src/game/`): rendering, prediction, HUD, audio, menus. Styles are in `src/styles/` |
| `scripts/` | `build.ts` (the build behind `npm start`), `dev.ts`, `fetch-assets.ts`, and the asset generators in `assets/` (textures, sounds, map and weapon models, light volumes, radar images) |
| `data/` | All tuning: weapons, movement, match rules and modes, bots, materials, destruction, graphics presets, public servers. Maps are in `data/maps/` |

Database: SQLite (`user/web.db`) by default. Set `DATABASE_URL=postgres://…` to use Postgres instead.
Passwords are hashed with argon2id. Sessions are signed HttpOnly cookies, and every form and API call
carries a CSRF token.

## Adding a map

A map is a JSON file in `data/maps/` built from prefabs: floors, walls with openings (`"soft": true`
makes them destructible, `"reinforce": true` lets defenders reinforce them), buildings, stairs, ramps,
crates, containers, barriers, vehicles, furniture, lights and terrain. It also contains gameplay data:
spawns, bomb-site and buy zones, callouts, cameras and practice positions. See `data/maps/qalat.json`.

The Afghanistan prefabs live in `shared/src/level/afghan.ts`: `mud_house`, `qala_wall`, `watchtower`, `rock_wall`,
`rocks`, `shop`, `awning`, `bunting`, `power_line`, `tree`, `prop`, `minar`, and the vehicle kinds `hilux`,
`technical`, `sedan`/`taxi`, `jingle`, `tanker`, `motorbike`, `btr` and `t55`. AFGHANISTAN.md lists their options.
Both maps are generated by Python scripts in `scripts/maps/` (`python scripts/maps/qalat.py data/maps/qalat.json`),
and `npx tsx scripts/maps/check.ts data/maps/*.json` checks a map: spawns to sites, every test route, and that no
room is sealed off.
The build generates its geometry, lighting and radar image. Bots need nothing extra: the navigation
mesh and tactical map are generated from the collision boxes and cached in `user/cache/`.
